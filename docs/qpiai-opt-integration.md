# QpiAI Opt

The adapter uses the SDK's documented `Binary`, `Model`, `Client`, and `solve` interfaces. It minimizes licence cost with explicit budget, required-language, and mandatory-dataset constraints. Rights-ineligible datasets are removed before model construction. The classical branch-and-bound result is computed independently and always returned in its own `classical_baseline` field.

The supported local integration is pinned in `backend/requirements-qpiai-opt.txt` (`qpiai-opt==0.0.9`). Local solving requires `Client(api_key=...)`; the SDK verifies the key online through `Client.verify_api_key()`, which posts to `/users/verify_secret_access_token`, before compute, while the model is solved with the local native runtime. A 401 response is mapped to `AuthenticationError` (the SDK describes the generic case as a missing or invalid API key and preserves the `ACCOUNT_REVOKED` code when supplied). Credential verification does not send the optimization model, and the SDK documents local solving as non-billable. The adapter explicitly uses `mode="local"` and `allow_platform=False`; it never enables paid platform execution or platform fallback. Only a result carrying the SDK's actual `execution_mode="local"` is reported as a completed QpiAI result.

For QUBO results, `solution` is a positional binary list while `variable_assignment` maps model variable names to values. Dispatch must decode `variable_assignment`; it then independently validates the selected facilities against the original chemistry and capacity constraints and computes the reported dispatch cost.

Set `QPIAI_OPT_API_KEY` in the server environment or secret manager (for local development, `.env`). The key is not included in logs or API result messages. Failure logs contain only the exception class, HTTP status, and safe upstream error code; exception text and request headers are intentionally omitted. The earlier authentication-failure evidence retained only the exception class, so it cannot establish a more specific upstream code. A later credential preflight for the configured local key returned `valid=true`, followed by a real local QUBO solve.

The API returns QpiAI Opt and the classical baseline separately. If QpiAI is unconfigured or fails, no classical result is copied into the QpiAI fields. Run the regression without a hosted solve using the regular backend suite; an explicit SDK local solve performs online key verification but does not submit paid platform work.
